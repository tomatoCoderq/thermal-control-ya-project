# Результаты: регрессия глубины (вариант B)

Чистая регрессия: бэкбон → 1 нейрон, лосс **SmoothL1 (Huber)**, таргет — глубина
залегания в **мм**. Обучение только на дефектных кропах (локализацию на инференсе
даёт сегментация). Каналы `p5+d1`, 50 эпох, нормировка признаков по-домену,
z-score таргета.

**Диапазоны глубин почти не пересекаются:** kaggle = 5–25 мм (5 дискретных),
tpu = 0.5–6.1 мм (непрерывно). Это определяет и дизайн, и чтение метрик.

---

## Эксперимент 2 — смешанный трейн, раздельный тест: Adam vs Muon

`train = kaggle + часть tpu-видео`, `test = held-out видео каждого домена`
(сплит по видео, без утечки). Метрики раздельно по доменам.

| optim | domain | MAE, мм | RMSE, мм | R² |
|---|---|--:|--:|--:|
| adamw | kaggle | 4.506 | 5.519 | 0.318 |
| adamw | tpu | 2.549 | 3.018 | −2.783 |
| adamw | **all** | 3.439 | 4.337 | 0.506 |
| **muon** | kaggle | **1.184** | **1.536** | **0.947** |
| **muon** | tpu | **1.731** | **1.956** | **−0.590** |
| **muon** | **all** | **1.483** | **1.778** | **0.917** |

### Muon — заметно лучше Adam во всех группах

- **MAE** падает в разы: kaggle 4.51 → **1.18 мм**, tpu 2.55 → **1.73 мм**,
  all 3.44 → **1.48 мм**.
- **R²** тоже лучше построчно: kaggle 0.318 → **0.947**, all 0.506 → **0.917**,
  tpu −2.78 → **−0.59** (менее отрицательный).
- Muon применяется к 2D+ скрытым весам (свёртки решейпятся к 2D) через
  ортогонализацию momentum-обновления (Ньютон–Шульц); bias/нормы/голова — в Adam.
  Разбиение групп и гибрид — в [optimizers.py](optimizers.py); включается
  `CFG.optim.name = "muon"`.

**Вывод:** для этого сетапа Muon — предпочтительный оптимизатор (лучше и по
абсолютной ошибке, и по R²). Adam остаётся дефолтом/бейзлайном.

## Про R²: почему на tpu он отрицательный (и это НЕ «плохая модель»)

$$R^2 = 1 - \frac{SS_{res}}{SS_{tot}}, \qquad SS_{tot}\propto \operatorname{Var}(y_{true})$$

R² сравнивает модель не с нулём, а с предсказанием **средней глубины по выборке**.
Знаменатель — разброс истинных глубин в этой группе. Если разброса почти нет,
знаменатель крошечный, и даже малая ошибка даёт отрицательный R².

В tpu-тесте каждое видео — **одна глубина** (все дефекты образца на одном
залегании), а видео в срезе мало → разброс таргета маленький:

| Домен (test) | видео | std(y_true) | Var (знаменатель) |
|---|---|--:|--:|
| kaggle | 3 | 6.69 мм | 44.7 |
| tpu | 3 | 1.55 мм | 2.4 |

Демонстрация: при **одинаковом** MAE=1.7 мм R² зависит только от разброса:

```
std(y_true)=7.0 мм  → R² = +0.936
std(y_true)=1.5 мм  → R² = −0.390   (≈ наш tpu)
std(y_true)=0.5 мм  → R² = −11.5
```

### Как читать метрики

- **На tpu основная метрика — MAE/RMSE (мм), а не R².** При нескольких
  одноглубинных видео R² статистически бессмыслен.
- Осмысленный tpu-R² получается только на **пуле предсказаний со всех k-fold**
  (там в выборке все 0.5–6.1 мм → большой разброс). Одиночный срез из 3–5 видео
  для R² не годится — отсюда и `r2=−5.09` на отдельном фолде.
- Дискретизированные `acc_quant`/`qwk_quant` осмысленны на kaggle-сетке; на tpu
  они вырождаются (`qwk_quant=nan`, когда после квантования один класс) — не
  использовать для tpu.

## k-fold по tpu-видео (устойчивая оценка)

tpu-видео мало (~20), одиночный held-out шумит. k-fold (K=4) по tpu-видео,
kaggle всегда в трейне целиком:

| Оценка | Значение |
|---|---|
| **tpu MAE (k-fold)** | **1.95 ± 0.16 мм** |
| tpu R² (по фолду) | сильно отрицательный (напр. −5.09) — см. раздел про R² |

MAE стабильна (±0.16 мм) — это надёжная цифра качества по глубине. Отрицательный
пофолдовый R² — ожидаемый артефакт малой дисперсии, а не деградация.

## Преимущество смешивания датасетов

Мотивация — kaggle и tpu покрывают **разные части шкалы** (5–25 мм и 0.5–6 мм).

- **Смешивание превращает экстраполяцию в интерполяцию.** По отдельности модель
  на kaggle не видит 0.5–5 мм и вынуждена экстраполировать вниз (регрессия это
  делает плохо). Объединённый трейн даёт сплошное покрытие **0.5–25 мм** → на
  tpu-диапазоне это уже интерполяция.
- **Эффект в цифрах:** в смешанном сетапе (Эксп.2, Muon) tpu MAE = **1.73 мм** и
  k-fold **1.95 ± 0.16 мм** — на непокрытом ранее диапазоне; при этом kaggle не
  ломается (MAE 1.18 мм, R² 0.947), т.е. «глубокая» зона остаётся точной.
- **Домен-инвариантность:** два материала/камеры/режима нагрева учат более общим
  признакам → лучше перенос на будущий третий образец.
- **Цена:** как только tpu в трейне, честно заявлять «перенос на tpu» уже нельзя —
  поэтому оставляем **held-out видео каждого домена** и метрики считаем раздельно
  (чтобы домен с бо́льшим числом кропов не задавил второй).

**Итог:** смешивать для трейна — да (покрытие + робастность); тест — held-out по
видео, метрики раздельно; на tpu смотреть MAE(мм), R² — только на широком пуле.

## Наблюдение: неуверенность на kaggle → нужны аугментации

На графике «оценённые глубины по видео» у **kaggle**-точек очень большие error-bar'ы
(разброс предсказаний по кропам одного видео) — напр. истинная глубина ~5 мм, а
среднее предсказание 10–15 мм со стандартным отклонением в несколько мм. То есть
модель даёт **нестабильный, сильно разный прогноз для разных кропов одного и того
же дефекта** и систематически **перелетает вверх**.

**Причина.** kaggle-кропов мало (~376, дефектные), каждая глубина представлена
единичными CAD-блоками; аугментаций нет (в [datasets.py](datasets.py) стоит
placeholder-комментарий, но преобразования не применяются). Модель переобучается
под конкретные кропы и не выучивает инвариантное представление → высокая дисперсия
на held-out видео.

**Что нужно — аугментации** (на этапе train, после нормировки признаков):

- **пространственные** (безопасны для карт TSR-коэффициентов): случайные
  горизонтальный/вертикальный флип, повороты на 90°, небольшой сдвиг окна кропа
  вокруг центра дефекта (jitter позиции);
- **фотометрические (мягко)**: небольшой поканальный гауссов шум и/или лёгкое
  масштабирование амплитуды — устойчивость к вариациям нагрева/камеры;
- опционально **mixup по глубине** (смешение кропов и таргетов) — сглаживает
  регрессию, но проверять аккуратно.

**Ожидаемый эффект:** меньше разброс предсказаний по кропам одного видео (уже
error-bar'ы), меньше систематический сдвиг, лучше перенос — особенно на «глубокой»
kaggle-зоне, где сейчас основная неуверенность.
