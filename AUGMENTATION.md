# Общая аугментация для U-Net и SegFormer

Ветка не содержит моделей и классификации. Она готовит один и тот же вход для
любого обычного сегментатора:

```text
температурное видео (T,H,W)
  → crop исследуемой области
  → PPT phase bins 1–3
  → resize 256×256
  → синхронная аугментация изображения и маски
  → image [3,256,256], mask [256,256]
```

Это непосредственно подходит для U-Net с `in_channels=3` и для обычного
SegFormer с тремя входными каналами.

## Crop рамки

ROI задаётся один раз для одинаковой установки камеры, а не для каждого кадра:

```yaml
sources:
  - root: archive/data
    masks: archive/labels/manual_mask
    object_roi: {x: 80, y: 25, w: 178, h: 190}
```

Если отдельное видео сдвинуто, используется override:

```yaml
files_meta:
  video_id:
    object_roi: {x: 82, y: 24, w: 176, h: 188}
```

Координаты проверяются командой:

```bash
python preview_object_crop.py --config configs/augmentation_ppt.yaml \
  --video-id R_002 --frames 0 440 900
```

Для проверенного `Sample 20 Static.mat` стартовый локальный ROI —
`{x: 80, y: 43, w: 178, h: 120}`. Он оставляет четыре видимых дефекта и не
захватывает верхний фон и нижний держатель.

## Что именно тасуется

Сначала весь crop приводится к `256×256`. Затем `RandomGridShuffle(grid=(2,2))`
делит его на четыре квадрата `128×128` и случайно переставляет их. Маска и все три
PPT-канала переставляются одинаково.

На шесть частей по умолчанию не делим: сетка `2×3` создаёт прямоугольные фрагменты
и больше искусственных границ. Если эксперимент нужен, достаточно заменить
`grid: [2, 2]` на `grid: [2, 3]`.

Полный train-набор преобразований:

- horizontal flip, `p=0.5`;
- vertical flip, `p=0.5`;
- `-7°`, `0°`, `+7°` с вероятностями `0.25`, `0.50`, `0.25`;
- grid shuffle `2×2`, `p=0.15` (опциональная абляция).

Для основного результата рекомендуется сравнить `shuffle p=0.0` и `p=0.15`:
перестановка блоков может уменьшить зависимость от положения дефекта, но создаёт
нефизические швы. На validation/test все аугментации отключаются автоматически.
