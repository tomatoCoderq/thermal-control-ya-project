# Планы: преобразование входных данных для CNN/ViT

Постановка: есть тепловизионная видеопоследовательность `(T, H, W)` с температурой по времени в каждом пикселе. Задача — сегментация дефектов, определение площади/координат, прогноз глубины. Вопрос: можно ли скармливать PCA (1 компонента) от каждого пикселя в CNN/ViT, и какие есть альтернативы преобразования исходного набора температур.

## Базовая идея

PCA по одному компоненту на пиксель — рабочий, но не оптимальный вариант входа. Это прямое расширение Seq 7 из статьи Chulkov et al. (2019) на всё изображение (там PCA считался для одной кривой в точке). Проблема: один компонент даёт всего один скалярный канал (2D-карту) и теряет часть временной динамики, которая коррелирует с глубиной дефекта. В статье TSR-производная (Seq 5) обошла PCA по точности: 1% против 2% (σ/h).

## Варианты сжатия временного стека `(T, H, W)` для входа CNN/ViT

**1. Многоканальное изображение (самый простой и оправданный путь).**
Взять k компонент PCA (3–5) как отдельные каналы вместо одного — "гиперспектральное" изображение, где каждый канал несёт часть temporal-вариации. Можно комбинировать разнородные признаки в каналы: PCA-1..3 + первая и вторая TSR-производная (Seq 5, Seq 6) + сырой пиковый ΔT + время до пика. Вход того же формата, что RGB-картинка, но с более информативными каналами — не требует переделки архитектуры.

**2. Коэффициенты полиномиальной аппроксимации (TSR-фичи).**
Для каждого пикселя — аппроксимация лог-кривой полиномом 5-й степени (как в Seq 4), сами коэффициенты (6 шт.) как каналы. Стандартный приём в NDT-литературе (TSR coefficient images), компактно и физически интерпретируемо; по идее не хуже чистого PCA, раз производные этой кривой были лучшими в статье.

**3. Фурье — амплитуда + фаза на нескольких частотах**, а не только фазограмма на одной низкой частоте (как Seq 8 в оригинале) — тоже многоканальный вход, богаче исходного.

**4. Готовые статистические дескрипторы на пиксель**: пиковый контраст, время до пика, скорость остывания, интеграл контраста по времени. Дёшево считается, интерпретируемо, хорошо заходит и в CNN, и в градиентный бустинг как baseline.

**5. Полное сохранение времени — 3D-CNN / video-ViT (ViViT, TimeSformer) или ConvLSTM.**
Подавать весь видеокуб как есть, без ручного сжатия — сеть сама извлекает нужное и для сегментации, и для регрессии глубины. Потенциально сильнее (глубина физически кодируется в *моменте* появления сигнала, а не только в форме кривой), но заметно более data-hungry — с малым числом дефектов на выборку такая модель, особенно ViT, скорее переобучится. Компромисс — ConvLSTM (2D CNN-энкодер по кадру + рекуррентная агрегация по времени): нужно меньше данных, чем чистому 3D-CNN/ViT.

## Рекомендуемый порядок экспериментов

1. Multi-channel baseline: PCA (неск. компонент) + TSR-производные + статистические дескрипторы → 2D U-Net для сегментации, та же карта признаков → regression head для глубины.
2. Если данных достаточно — сравнить с end-to-end 3D-CNN/ConvLSTM на сырых кадрах, чтобы проверить, даёт ли отказ от ручной предобработки прирост точности.

## Архитектура: U-Net (H,W,6) → сегментация + per-instance регрессия глубины

Общая схема: `(H, W, 6)` (коэффициенты полинома 5-й степени, по каналу на коэффициент) → энкодер U-Net → декодер → сегментационная маска `(H, W, 1)` (или `(H, W, N_classes)`, если несколько типов дефектов). Multi-task: один backbone, две головы.

**Голова глубины — не наивный глобальный linear head.** Если на кадре одновременно несколько дефектов с разной глубиной (как D1–D5 в статье), глобальный average-pooling + linear по всему изображению даст один усреднённый ответ на все дефекты сразу — неправильно. Вместо этого — per-instance регрессия:
1. U-Net выдаёт маску сегментации → connected components / instance models разделяют дефекты.
2. Для каждого отдельного дефекта — masked average/max pooling признаков декодера (или bottleneck) по его маске → один вектор на дефект.
3. Вектор → линейный слой (или небольшой MLP) → глубина этого конкретного дефекта.

Архитектурно похоже на Mask R-CNN: сначала сегментация/детекция экземпляров, затем атрибут (глубина) предсказывается отдельно для каждого найденного объекта.

**Дополнительные технические моменты:**
- **Нормализация каналов.** Коэффициенты полинома (при x⁵ и свободный член) различаются на порядки по масштабу — обязательна стандартизация (z-score) каждого канала перед подачей в сеть.
- **Баланс лоссов.** Итоговый loss = сегментационный (Dice/BCE) + регрессионный (MSE/MAE по глубине) с весами между ними; можно начать с фиксированных весов, затем попробовать uncertainty-weighting (Kendall et al.) для автобаланса.
- **Дополнительные каналы для головы глубины.** Если точности одних коэффициентов полинома не хватит — добавить в вход амплитуду/время пика первой производной (Seq 5, TSR) как отдельные каналы: по статье именно этот признак сильнее всего коррелирует с глубиной.
